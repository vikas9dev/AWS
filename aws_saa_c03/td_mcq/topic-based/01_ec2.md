# EC2

## **Question 1**

**A company needs to deploy at least two Amazon EC2 instances to support the normal workloads of its application and automatically scale up to six EC2 instances to handle the peak load. The architecture must be highly available and fault-tolerant as it is processing mission-critical workloads.**

**Options:**

* Create an Auto Scaling group of EC2 instances and set the minimum capacity to 2 and the maximum capacity to 6. Deploy 4 instances in Availability Zone A.
* Create an Auto Scaling group of EC2 instances and set the minimum capacity to 4 and the maximum capacity to 6. Deploy 2 instances in Availability Zone A and another 2 instances in Availability Zone B.
* Create an Auto Scaling group of EC2 instances and set the minimum capacity to 2 and the maximum capacity to 6. Use 2 Availability Zones and deploy 1 instance for each AZ.
* Create an Auto Scaling group of EC2 instances and set the minimum capacity to 2 and the maximum capacity to 4. Deploy 2 instances in Availability Zone A and 2 instances in Availability Zone B.

<details>
<summary><strong>Answer & Explanation</strong> 📝</summary>

✅ **Correct answer:**
**Create an Auto Scaling group of EC2 instances and set the minimum capacity to 4 and the maximum capacity to 6. Deploy 2 instances in Availability Zone A and another 2 instances in Availability Zone B.**

### Why this is correct

* The application is **mission-critical**, so it must survive an **entire Availability Zone failure**.
* If the baseline is only **1 instance per AZ**, losing one AZ leaves **only 1 instance**, which violates the requirement of *at least two instances for normal workload*.
* By setting:

  * **Minimum capacity = 4**
  * **2 instances per AZ**
* The system guarantees:

  * Normal operation: 4 instances
  * After losing one AZ: **2 remaining instances**, still meeting the baseline requirement
* **Maximum capacity = 6** allows scaling during peak load.

### Why the other options fail

* <span style="color:red"><strong>❌ All instances in one AZ</strong></span> → Not fault-tolerant.
* <span style="color:red"><strong>❌ Min = 2 across 2 AZs (1 per AZ)</strong></span> → AZ failure leaves only **1 instance**.
* <span style="color:red"><strong>❌ Max = 4</strong></span> → Does not meet peak requirement of 6 instances.

💡 **Key exam insight (AWS SAA):**
For *mission-critical workloads*, AWS expects **baseline capacity to be preserved even after an AZ failure**.

## **Question 2**

**You are automating the creation of EC2 instances in your VPC. You wrote a Python script to trigger the Amazon EC2 API to request 50 EC2 instances in a single Availability Zone. However, after 20 successful requests, the subsequent requests failed.
What could be a reason for this issue and how would you resolve it?**

**Options:**

* By default, AWS allows you to provision a maximum of 20 instances per region. Select a different region and retry the failed request.
* By default, AWS allows you to provision a maximum of 20 instances per Availability Zone. Select a different Availability Zone and retry the failed request.
* There is a vCPU-based On-Demand Instance limit per region which is why subsequent requests failed. Just submit the limit increase form to AWS and retry the failed requests once approved.
* There was an issue with the Amazon EC2 API. Just resend the requests and these will be provisioned successfully.

<details>
<summary><strong>Answer & Explanation</strong> 📝</summary>

✅ **Correct answer:**
**There is a vCPU-based On-Demand Instance limit per region which is why subsequent requests failed. Just submit the limit increase form to AWS and retry the failed requests once approved.**

### Explanation

* AWS no longer enforces EC2 limits purely by **number of instances**.
* Instead, EC2 uses **vCPU-based On-Demand limits per region** (for each instance family).
* After provisioning ~20 instances, your account likely **exhausted the available vCPU quota**, causing subsequent launch requests to fail.
* This applies **regardless of Availability Zone**.
* The correct resolution is to **request a service quota (limit) increase** for the required vCPU capacity.

### Why the other options are incorrect

* <span style="color:red"><strong>❌ 20 instances per region</strong></span> – This is outdated; limits are vCPU-based, not instance-count based.
* <span style="color:red"><strong>❌ 20 instances per Availability Zone</strong></span> – No such default AZ-level instance limit exists.
* <span style="color:red"><strong>❌ EC2 API issue</strong></span> – Re-sending requests will fail again until the quota issue is resolved.

💡 **Exam tip (AWS SAA):**
If EC2 launches fail after a certain count, always think **Service Quotas → vCPU limits**, not AZ or API errors.

You are limited to running On-Demand Instances per your vCPU-based On-Demand Instance limit, purchasing 20 Reserved Instances, and requesting Spot Instances per your dynamic Spot limit per region. New AWS accounts may start with limits that are lower than the limits described here.

If you need more instances, complete the Amazon EC2 limit increase request form with your use case, and your limit increase will be considered. Limit increases are tied to the region they were requested for.

</details>
